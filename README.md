# Wobble Rush

An original Roblox party-royale for up to 30 players. Round, squishy **Bloblets** wobble through
randomly shuffled mini-game rounds until one winner is left.

This repository is a [Rojo](https://rojo.space) project: all game code is Luau in `src/`, and
Rojo syncs it into Roblox Studio. The lobby, characters and UI are all generated by code, so
there are no models or images to upload.

## 1. Connecting Rojo to Roblox Studio

You need three things: this folder on your computer, the Rojo command-line tool, and the Rojo
plugin inside Studio.

### Get the code

```bash
git clone https://github.com/eminhqn/rblxfllgys.git
cd rblxfllgys
```

### Install Rojo (choose one)

**Option A: VS Code (easiest)**
1. Install [Visual Studio Code](https://code.visualstudio.com/) and open this folder in it.
2. Accept the "recommended extensions" prompt. That installs Rojo, Luau Language Server,
   StyLua and Selene (listed in `.vscode/extensions.json`).
3. Open the command palette (`Ctrl+Shift+P`) and run **Rojo: Open Menu**. It will offer to
   install Rojo and the Studio plugin for you.

**Option B: Rokit (command line)**
1. Install [Rokit](https://github.com/rojo-rbx/rokit).
2. In this folder run `rokit install`. That installs the exact tool versions in `rokit.toml`
   (Rojo 7.7.1, Selene, StyLua, luau-lsp).
3. Run `rojo plugin install` to add the Rojo plugin to Studio.

### First time: build the place file

Some settings (streaming, lighting, "don't load the default avatar") can't be changed by live
sync, so build the place once and open it:

```bash
rojo build -o WobbleRush.rbxl
```

Open `WobbleRush.rbxl` in Roblox Studio, then **File → Save to Roblox** if you want it in your
account. You only need to rebuild if `default.project.json` changes.

### Every session: live sync

1. In the terminal (or the VS Code Rojo menu): `rojo serve`
2. In Studio: **Plugins** tab → **Rojo** → **Connect** (default `localhost:34872`).
3. Edit files in `src/`. Changes appear in Studio straight away.

> Always edit the code in `src/`, not inside Studio. Rojo overwrites script changes made in
> Studio.

## 2. Testing in Studio

Press **Play** (F5) for a solo test. For multiplayer checks (grabbing, eliminations, spectating),
use **Test** tab → **Clients and Servers** → choose **2–3 players** → **Start**.

Keep the **Output** window open (View → Output). There should be no red errors.

> **One-time setting for Milestone 2:** select **Workspace** in the Explorer and set
> **StreamingIntegrityMode** to **MinimumRadiusPause** in Properties (or rebuild the place with
> `rojo build`). It makes sure the arena has loaded around you before you can fall.

### Milestone 16 checklist: spectating and revives

Test with bots on (the default): press **Play** (F5), then **PLAY**, and play a race (put
`"ConveyorCanyon"` in `StudioForceRounds` for a quick one; set it back afterwards). To test
REVIVE with a RESPAWN, buy a **3 Respawns** pack in the ITEMS shop first (Studio purchases are
free test purchases).

**Spectating while you wait**
- [ ] Finish a race: QUALIFIED!, and about 2.5 seconds later the screen blinks and you're
      watching someone still racing. The bar says YOU'RE IN THE NEXT ROUND! with no lobby button;
      Q / E (LB / RB) switch players, and you only get players still racing.
- [ ] Whoever you're watching finishes: you move on to someone still racing.
- [ ] The next round loads: you're back to your own Bloblet, playing.
- [ ] Reach the summit in Rising Tide early: the same (you watch the others climb).

**Knocked out: back to the lobby and watching again**
- [ ] Get knocked out: ELIMINATED!, then you're watching (as before). BACK TO LOBBY takes you
      to the lobby (with a controller, the B picture is on the button).
- [ ] In the lobby, under PLAY there's **WATCH MATCH** (D-pad left). It takes you straight back
      to watching, with no ELIMINATED! stamp. You can go back and forth as often as you like.
- [ ] WATCH MATCH is gone once the match is over (the winner celebration).

**Revive**
- [ ] Knocked out (not in the final) with a RESPAWN: the spectate bar shows BACK TO LOBBY and
      **REVIVE · 1 RESPAWN** side by side, with the controller's B and A pictures on them (R on a
      keyboard); the lobby menu shows it too (D-pad right). Press it: REVIVED! YOU'RE IN THE NEXT
      ROUND, one RESPAWN is used, and you watch until the next round, which you play.
- [ ] Knocked out right at the end of a round (not finishing a race): after ROUND OVER the next
      round waits (the round-over timer runs on) until you've revived, gone back to the lobby, or
      had 10 seconds to decide (`Config.Items.ReviveTime`). Revive in that time and you're in
      the very next round.
- [ ] Don't revive and let the next round start: REVIVE disappears (it's only ever for the round
      after the one you went out in).
- [ ] Only once a match: knocked out again later, there's no REVIVE.
- [ ] No REVIVE once the final is on (or after being knocked out of the final).
- [ ] With no RESPAWNS and `Config.Items.ReviveProductId` set, REVIVE shows the Robux price and
      opens the purchase screen (the next round waits while it's open). Buying it brings you back
      straight away. Once you've bought one, it isn't offered again that match. With
      `ReviveProductId = 0` and no RESPAWNS, there's no REVIVE button.
- [ ] Revive when the round you're out of leaves only one player through (or nobody): there's
      no next round, so the match ends as before, and you get NO NEXT ROUND: YOUR REVIVE IS A
      RESPAWN AGAIN (your RESPAWN count goes back up).
- [ ] The mid-round respawn offer (knocked out with a RESPAWN) works as before; REVIVE only
      appears once you're out of the arena.

### Milestone 15 checklist: bots

Bots are on by default (`Config.Bots` in `src/shared/Config.luau`). In Studio, press **Play**
(F5) and then **PLAY**: the countdown starts with just you, and when it ends **11 bots** join you
to make 12 (`FillTo`). Set `Config.Bots.Enabled = false` to play without them. To watch a
particular round, put it in `StudioForceRounds` as usual (set it back to `table.freeze({})`
afterwards). When you're knocked out, spectating is the easiest way to watch the bots play.

**In every match**
- [ ] The bots arrive with the match: candy names (Jellybean, Sprinkles, Gumdrop...) over their
      heads, random colours, hats and outfits, and nobody shares a name with a player. They never
      appear in the lobby.
- [ ] Bots count as players everywhere: the PLAYERS LEFT counter, QUALIFIED / ELIMINATED,
      spectating (they're in the list), team outlines and team scores.
- [ ] Bots run, jump onto ledges, jump (and dive) over gaps, kick and grab whoever's in front of
      them now and then, get knocked over by hazards, kicks, slaps and dives, and get up again.
- [ ] Bots are as good as they get by default (`SkillMin = SkillMax = 1`): full player speed,
      every hazard spotted at once, no fluffed or mistimed jumps, always the hard shortcut, the
      fastest legal tugging, and plenty of kicks. For a mix, set `SkillMin = 0.3` and
      `SkillMax = 0.85`: then sharp ones run a bit faster, dodge more and fluff fewer jumps, and
      clumsy ones fall off more.
- [ ] A bot that gets stuck hops, then tries sideways, and in a race goes back to its checkpoint.
- [ ] A knocked-out bot disappears (bots don't spectate). If a bot wins, it gets the podium and the
      winner celebration like a player would. No Crowns, Gumdrops or XP go to bots, and nobody's
      saved data changes because of them.
- [ ] (Published game only; Studio always uses its short countdown.) A match starts 15 seconds
      after the first player presses PLAY when fewer than 4 have queued
      (`Config.Bots.QueueCountdown`); other players can still join during those 15 seconds.

**Races**
- [ ] **Conveyor Canyon**: bots take the fast forward lanes, lean into the side sweepers and the
      bridge belts so they aren't carried off the edge, jump the gaps between them, step out of the
      way of crates (landing circles and crates sliding along belts) and run up the slow ramp to the
      finish. A bot standing still on a belt holds its place against it.
- [ ] **Bounce Pad Gauntlet**: bots bounce across the trampolines (steering for where a moving
      pad will be when they come down), go for whichever sliding platform of a row is coming
      nearest, wait at the edge until a jump will land on it, jump, ride it, and time the jump off
      it the same way (straight across to the nearest floor).
- [ ] **Sugar Slopes**: bots climb the hill, keep to the safe line on the icing, and some take the
      toffee shortcut (the sharper the bot, the more likely). They jump + dive each gap, timing
      the dive to come down just onto the next island, and stop their belly slide before its far
      edge. A bot that falls in takes the toffee belts round the side after that. On the hill and
      the ridge they see the gumdrops coming (where each one will be, from its lane arrows on) and
      step across to a line none of them will roll down, or stop for a moment; sharp bots look
      further ahead. They still get caught now and then when the ridge is crowded.
- [ ] **Tumble Tower**: bots climb the steps, hop onto the gliding platforms and off them when the
      gap is short, pass between the hammers, cross the spike stairs on the safe side, and time
      their jumps from lift to lift as they go up and down.
- [ ] **Splash Slide**: bots slide down, picking an easy or hard way at each pool. On the water
      they dive into a belly slide (except just before a gap or a ramp) and lean into the side
      currents, so they stay on the open chutes. They jump every gap on the shortcuts and at the
      lip of each ramp (JUMP and SKI JUMP), clearing it with room to spare. A hammer swinging
      across ahead gets jumped at a moment that clears its head, including the two close
      together near the bottom of the second shortcut. They almost never get hit.
- [ ] Every race: some bots finish (and qualify), clumsier ones are slower or fall off and go back
      to their checkpoint. A bot sent back after setting off down a hard way (a shortcut, a jump)
      takes the easy way there for the rest of the round.

**Survival and finals**
- [ ] **Rising Tide**: bots spread over the three stairways and climb them plank by plank ahead of
      the water (jumping early enough to clear each plank's edge, never diving past it), then jump
      up onto the golden top and qualify. They float and swim like players: one that falls in
      swims to the nearest plank it can jump onto and carries on from there.
- [ ] **Balloon Barrage**: bots wander the middle, stepping out of a balloon's lane or jumping it.
- [ ] **Pinwheel Panic**: bots jump the low pink bar (and mostly don't jump into the high blue
      one), and step in a ring before theirs drops, ending up on the bouncy middle.
- [ ] **Jiggly Jelly**: bots hop from square to square before theirs sinks too far.
- [ ] **Cloud Crown**: bots move in ahead of the crumbling edge and get off a split line before it
      drops (sharp bots in good time, clumsy ones only once it greys out).
- [ ] **Popcorn Plates**: bots keep hopping to the plates round theirs and drop to the next floor
      when there are none left. They never dive (outside races bots don't), and never jump at a
      gap with nothing across it.
- [ ] **King of the Cake**: bots climb the macarons tier by tier, then fight for the top (their
      KING meter fills like yours).

**Team rounds**
- [ ] **Paint Grab**: bots spread out painting tiles that aren't their team's yet, and go for
      power-ups near them.
- [ ] **Gumball Goal**: bots get behind a gumball and push it towards their own jar (going round
      it rather than pushing it the wrong way), sometimes diving into it.
- [ ] **Tug of Wobble**: bots run to their side of the rope, grab it and pull (the flag moves for
      them as it does for players), and grab again after falling in the goo.
- [ ] **Egg Scramble**: bots pick up eggs (golden ones first), carry them up the ramps to their
      nest, and sometimes chase down the other team's carriers to knock the egg out.
- [ ] **Sprinkle Hills**: bots go up the ramps to hills their team doesn't hold (or is losing),
      mill about on top and jump the spinning bar on hill B.

**Settings** (`Config.Bots`): `FillTo` (players + bots in a match), `QueueCountdown`,
`SkillMin` / `SkillMax` (0 = clumsy, 1 = as good as they get; both 1 by default), `KickRate` /
`GrabRate` (per second, with someone in front) and `Names`.

**Seeing what a bot is thinking:** set `Config.Studio.ShowBotThoughts = true` and press Play. A
dark line over each bot says what it's doing: e.g. `route 7/31 · 12 away`, `route 12/31
waiting for a platform`, `waiting for Hammer`, `at an edge`, `stuck 2.4s`, `[Ragdoll]`. If a bot
misbehaves somewhere, that line (and the round) is what to report. Set it back to `false`
afterwards.
- [ ] Bots run straight to where they're going and settle there: no circling round a spot.
- [ ] Bots jump at the very edge of a gap (and dive over wide ones), jump walls and ledges in
      their way, and stop at edges in rounds where falling off is out.
- [ ] A bot that can't get anywhere (stuck on something, or fallen off under a platform) hops,
      sidesteps, and in a race is put back on its checkpoint within a few seconds.

**Server performance with bots (stress test)**

Bots are simulated by the server, so a match full of them is the heaviest the server gets. To
measure it, in `src/shared/Config.luau` set `Config.Studio.ProfileBots = true` and
`Config.Bots.FillTo = 30` (you plus 29 bots), then use **Test → Clients and Servers** with **1**
player (the server gets its own window and Output; in a plain Play it shares a process with your
client) and press PLAY.
- [ ] Every 10 seconds the server's Output prints a `[BotProfiler]` summary: the server's frame
      rate, how many milliseconds per frame BotMotor (moving the bots), BotWorld (moving the
      platform copies bots stand on, hazard hits) and BotBrain (deciding; with its goals, gumdrops
      and hazards broken out) take, the total for all bots, and raycasts a second.
- [ ] With 29 bots the server stays at about 60 fps and **all bots** stays under about 4 ms per
      frame (a quarter of a frame), including the heavy spots: Gumdrop Ridge on Sugar Slopes
      (gumdrop planning), Bounce Pad Gauntlet and Tumble Tower (planned jumps), Jiggly Jelly (many
      jelly squares). In a normal 12-player match it should be well under half that.
- [ ] **Ctrl+F6** (in the server window) opens the MicroProfiler: BotMotor, BotWorld and BotBrain
      show up as labelled blocks in each frame. No frame should have a tall BotBrain spike: bots
      take turns thinking across frames.
- [ ] Set `ProfileBots` back to `false` and `FillTo` back to `12` when you're done.

### Milestone 14 checklist: team rounds, tutorial, music, double XP and the premium track

back to back, set `StudioForceRounds = table.freeze({ "TugOfWobble", "EggScramble", "SprinkleHills" })`

**Buying only in the cosmetic shop**
- [ ] The customise tabs (COLOUR, PATTERN, EYES, HAT, OUTFIT, EMOTE, SLAPPER) no longer sell
      anything: they show what you own (to wear) and the reward track's items (LV 8, PREMIUM 4...).
      There's no BUY button there any more.
- [ ] Everything that costs Crowns (the old shop items plus the 33 that used to be sold in the
      tabs: colours like Snow and Rose Gold, Spots, Big Eyes, Beanie, Crown, Hero Cape, Spin,
      Spatula, Frying Pan...) now comes round in the **cosmetic shop**. Things you already
      bought are still yours.
- [ ] The **DAILY SHOP** now has **8 items** in two rows, with the **WEEKLY SHOP**'s 2 under them.
      The shop scrolls (mouse wheel, drag, or moving down onto the weekly row with a controller
      scrolls it for you). Try `Config.Studio.ShopDaysAhead` to see other days' shops.

**Grab (every round)**
- [ ] Grab reaches further than before, and works on anyone in front of you (not just straight
      ahead).
- [ ] **Hold GRAB**: you keep reaching (arms out, a little slower) and grab the first player, egg or
      rope that comes in reach, so you can hold it and walk into them. Let go to stop.
- [ ] Tapping GRAB again quickly works (a short cooldown).

**Tug of Wobble (team)**
- [ ] Two team platforms at either end of a long wooden bridge over goo. The bridge is in six
      pieces that rock side to side, each a little out of step, and rock harder in the second half.
- [ ] A pink-and-white rope with knots runs along the middle with a yellow flag over its middle.
      The bridge's rails are in each team's colour at its end, with a "CORAL PULL!" sign over each
      half and a glowing line across the bridge in each team's colour.
- [ ] Walk up next to the rope on your side of the flag: **GRAB THE ROPE! (HOLD SHIFT / HOLD LT /
      HOLD GRAB)** shows near the bottom of the screen. Grab: you take hold, turn to face the
      flag, lean back with your arms out, and can't walk.
- [ ] Holding on, the prompt says **MASH SPACE / MASH A / MASH JUMP**: each press tugs (you heave
      back, the prompt bounces) instead of jumping. The faster your team mashes (for its size),
      the faster the flag slides your way, and everyone holding the rope slides along with it.
      Stop mashing and it slows to a stop. The counter shows how many of each team are pulling,
      and the team score bar shows how close the flag is to each line.
- [ ] Press GRAB again (or dive, or kick) to let go. Getting kicked, slapped, grabbed or shoved
      away from the rope makes you let go, so run over and knock the other team off it. You can't
      hold the rope on the other team's side of the flag.
- [ ] Drag the flag over your line and your team wins straight away (**CORAL WINS!**). Fall in the
      goo and you're back on your platform. At time up, the team the flag is nearer wins; dead
      centre is a tie and both teams go through.

**Egg Scramble (team)**
- [ ] A two-storey wooden chicken den with windows and an open roof frame. Downstairs: a straw
      floor with hay bales. Upstairs: a loft at each end (barn doors on its front, a low fence
      along its edge) with your team's straw nest on it ("CORAL NEST"). Each loft has two ramps up
      against the long walls and a trampoline in front of it.
- [ ] Three hens sit in nesting boxes on a beam high over the middle. At GO they lay eggs that
      drop down to the floor and bounce about; more keep coming. Every 25 seconds one lays a
      shining **golden egg** (A GOLDEN EGG! WORTH 3!).
- [ ] Teams start up on their own loft. **GRAB** near an egg picks it up (hold GRAB and just run
      into one): your Bloblet holds it over its head with both arms up and runs a little slower,
      and **TAKE IT UP TO YOUR NEST!** shows on screen.
- [ ] Carry it up a ramp (or bounce up the trampoline) into your own nest to score (a little egg
      joins the pile there, the score bar goes up). **DIVE** while carrying throws the egg forward;
      a throw that lands in your nest counts.
- [ ] Get kicked, slapped or grabbed while carrying and the egg pops out of your hands.
- [ ] Most eggs at time up wins; a tie sends both teams through.

**Sprinkle Hills (team)**
- [ ] A big round pink candy island covered in sprinkles with three big hills, well spread out: A
      and C either side, B in the middle and taller with a purple spinning bar on top. Wide ramps
      lead up each hill from both teams' sides, and trampolines bounce you up the outer side of A
      and C.
- [ ] Each hill has a white ring round its top, a flag on its edge and a floating "HILL A" label.
- [ ] Stand on a hill with more of your team than the other team: a bar fills under its label for 3
      seconds, then the ring, flag and label turn your colour and **CORAL TOOK HILL B!** pops up.
- [ ] Each hill your team holds scores a point a second (the score bar counts to 100). First to 100
      wins straight away; otherwise the most points at time up (a tie sends both).

**The tutorial**
- [ ] Brand-new players (a Studio test with saving off counts as new) get **NEW TO WOBBLE RUSH?**
      a few seconds after joining: PLAY TUTORIAL (A) or NO THANKS (B). It's only offered once.
- [ ] PLAY TUTORIAL puts you on a floating island west of the plaza. A panel at the top shows
      **TUTORIAL · STEP 1 OF 6**, what to do and the key for it (keyboard, controller or touch,
      matching what you're using), and a LEAVE button (Back / View on a controller).
- [ ] The steps: walk to the glowing ring; jump onto the yellow step; jump then dive over the gap;
      grab the pink GRAB ME dummy; kick the yellow KICK ME dummy; bounce on the trampoline up to
      the finish under the crown. Each one clicks to the next with a sound. Falling off puts you
      back at the start of the step.
- [ ] At the end: **TUTORIAL DONE! +100 GUMDROPS** (only the first time), then you're back in the
      lobby. **MENU → TUTORIAL** plays it again. Pressing PLAY and joining a match ends it.

**Music and sounds**
- [ ] The lobby has its own gentle song. Each round plays its own song, quieter over the round card
      and countdown, full from GO, fading out at ROUND OVER. It's quiet while the arena loads and
      while the winner celebrates.
- [ ] With 10 seconds left in a round the music speeds up, the hi-hats double and a HURRY sting
      plays.

### Milestone 13 checklist: four new rounds

There are now 14 rounds: 5 races, 4 survival, 2 team and 3 finals. To play one on its own, set
`StudioForceRounds` in `src/shared/Config.luau`, e.g. `table.freeze({ "TumbleTower" })`, and set it
back to `table.freeze({})` afterwards. Ids: `TumbleTower`, `SplashSlide`, `JigglyJelly`,
`KingOfTheCake`. Solo is fine for all four; the final's KING meter is best tested with 2 or 3
players (**Test → Clients and Servers**), so you can knock each other off.

**Tumble Tower (race)**
- [ ] A giant pink candy-striped tower with a cherry on top. The course zigzags up its face in
      four ledges, each one higher and a little further back, with glass rails on the tower side.
- [ ] **Candy Steps:** a wide apron off the start pad, floating coloured steps up, then two yellow
      platforms gliding back and forth over a gap. Ride them across.
- [ ] A **CHECKPOINT** on the corner landing, then **Hammer Hall:** a long ramp with five giant
      candy hammers on posts swinging across it. A hammer that hits you knocks you flying (off the
      ledge if you're unlucky); a slow tap near the end of a swing doesn't.
- [ ] **CHECKPOINT**, then **Spike Stairs:** steps with spike traps. Some pop up on a timer (the
      spikes peek out just before they rise, so you can see them coming), others cover half the
      step and never go down: take the other half. Two traps across the whole ledge at the top
      need timing. Spikes fling you up and back.
- [ ] **CHECKPOINT**, then **Sky Lifts:** platforms riding up and down, two more hammers, and a
      gliding last platform up to the **FINISH** on top of the tower.
- [ ] Falling off anywhere puts you back at your last checkpoint.

**Splash Slide (race)**
- [ ] A start pad on a tower high in the sky, with glass funnelling you onto a water slide that
      winds down to a big pool at the bottom.
- [ ] The slides are smooth troughs: a blue water floor with rounded, coloured sides that curve up
      into glass rails. Steering into the side rides you up the curve and back down, with no
      sharp edge to catch on. Bends are long and gentle, and there's no bump or step where one
      piece meets the next, or where a slide meets a pool.
- [ ] The water carries you along (white foam arrows point downhill); you can still steer, jump and
      dive. **Dive** onto the water and you belly slide the whole way down to the next pool, a bit
      faster than the water; it never slows you down. Jump to get up. Others see you belly
      sliding too.
- [ ] Each splash pool is a **checkpoint** and splits into routes, each with a sign over it. They all
      meet again at the next pool:
  - [ ] **LONG WAY (EASY)** (green): wide and walled, swinging out wide round big gentle bends. Slower, but hard
        to fall off.
  - [ ] **SHORTCUT (HARD)** (orange): a narrow, straight chute (barely twice a Bloblet wide) with
        faster water and only a low lip at the edges (no walls). Fall off and you're back at the
        pool. On it:
    - [ ] Candy hammers swinging fast across it (3 on the first, 4 on the second, two of them
          close together). Time them, slow down (pull back) or jump them.
    - [ ] **Side currents**: stretches of paler, foamy water with white arrows that shove you
          sideways towards the edge. Steer against the arrows; they change direction from one
          stretch to the next.
    - [ ] A **gap to jump yourself** (a yellow line marks the edge). Ride over it without
          jumping and you fall.
  - [ ] **JUMP (MEDIUM)** (yellow, second pool): walled and straight, with a yellow ramp that
        throws you over a 15-stud gap. Riding the ramp is enough.
  - [ ] **SKI JUMP (HARD)** (purple, last pool): narrow and wall-less, two side currents on the
        way, then a steep ramp over a 20-stud gap and a hammer after the landing. Just riding
        the ramp may fall short: belly slide down to it or jump at the lip to make it.
- [ ] The first slide and the long ways have peppermint bumpers to steer round. The last pool
      has an orange spinning bar to jump.
- [ ] Taking the shortcuts and jumps gets you down noticeably sooner than the long ways (about 17
      seconds of sliding against about 22).
- [ ] The **FINISH** is the pool deck at the bottom. Rubber rings float in the pool round it.

**Jiggly Jelly (survival)**
- [ ] A round floor of glassy jelly squares in five colours, over a big white bowl of brown syrup,
      with sugar crystals round its rim and gummy bears watching from round the outside.
- [ ] Standing on a square makes it wobble and sink under you. Stay on it about 2 seconds and it
      sinks all the way and melts away (it vanishes), dropping you into the syrup: you're out.
- [ ] Step off a sinking square and it slowly bobs back up. Melted squares grow back after a few
      seconds.
- [ ] As the round goes on squares sink faster (about 1 second near the end) and take longer to
      grow back, and after about 70 seconds they stop growing back, so the floor gets full of
      holes. Keep moving!
- [ ] About 12 seconds in, **THE SYRUP IS RISING!** pops up and the syrup slowly rises for about
      a minute. It stops a little below the jelly, so a square that's all the way up is always
      safe. As it rises, a sinking square dunks you in the syrup before it has even melted
      (near the end, after about half a second on one square), so you can't stand on one
      square for long.
- [ ] With 2 players: two people on one square sink it just as fast as one, and you both see the
      same squares sinking and the same syrup level at the same time.

**King of the Cake (final)**
- [ ] A giant three-tier cake on a plate: a pink bottom tier, a chocolate middle tier and a yellow
      top tier, each with frosting, drips and sprinkles. All three tiers wobble gently, each in
      its own rhythm.
- [ ] You start on the bottom tier. The tiers are too tall to jump, so climb the **macaron steps**
      (4 round the bottom tier, 3 round the middle).
- [ ] A **KING** meter shows at the top of the screen (**0 / 20**). It fills while you're on the
      top tier (standing or jumping above it) and stops when you leave. The counter under the
      round name shows who's leading, e.g. **KING: SAM 12/20**, or **CLIMB TO THE TOP!**.
- [ ] A big candle stands in the middle of the top tier, and its red bar sweeps round: jump it or
      get knocked flying.
- [ ] Halfway through **THE CAKE IS WOBBLING!** pops up: the candle bar speeds up and over the next
      20 seconds the tiers wobble harder (smoothly, no jumps).
- [ ] At 15 seconds on top, **SAM IS NEARLY KING!** pops up for everyone.
- [ ] The first to 20 seconds wins straight away. Falling off the cake (onto the plate) knocks you
      out. If everyone else falls off, the last one on the cake wins. If time runs out, whoever
      is still on the cake with the fullest meter wins (**SAM IS KING OF THE CAKE!**).
- [ ] After the round the KING meter is gone (and it never shows in other rounds).

**Shields and the new hazards**
- [ ] With a **SHIELD** picked, a hammer hit, spike trap or the candle bar cracks the shield and
      gives you a small bump instead of knocking you over.

**Who decides what**
- **Movement** runs on your own device (Roblox gives each player ownership of their character's
  physics), so it responds instantly. The server checks positions twice a second and snaps back
  impossible speed or teleports (`MovementValidator`).
- **Dive and grab** play instantly on your screen, and a request goes to the server. The server
  checks cooldowns and state, picks the grab target itself, and publishes the result as
  character attributes (`Action`, `Grabbing`, `GrabbedBy`, `Ragdolled`). Other clients animate
  from those. Rejected requests cancel the local prediction.
- **Every remote** is rate-limited and type-checked on the server (`ActionService`,
  `CharacterService`). Clients only send intent, never results.
- **Moving hazards** are animated on each client from the shared server clock, so the server
  sends no per-frame data. Everyone sees the same pose, and hits are judged against what you
  actually see.
- **Animation** (squash/stretch, eyes, feet) is client-only via `Motor6D.Transform` and
  `SpecialMesh.Scale`. With 30 players, only Bloblets close by and on screen are animated every
  frame; others update less often, spread across frames.
- **Celebrations and camera moments** are client-only too: the server publishes the winner, the
  podium spot and the arena's bounds as `MatchState` attributes, and each client builds its own
  crown, fireworks and camera path from them.
- **Sounds** play on each client: your own from your movement, other players' from their
  replicated `Action` / `Ragdolled` attributes, all through one `SoundGroup`.
- **Bots** are run entirely by the server. A bot is a stand-in for a player that the rounds treat
  like anyone else (`Bots`); its Bloblet is a server physics body (`BotMotor`) carrying the same
  attributes players' Bloblets do (plus `UserId`, `DisplayName` and `MatchStatus`, read through
  `Shared/Competitors`), so clients animate, outline and spectate it like a player. Hazards that
  only move on clients get a server copy that only bots stand on (`BotWorld`), and hits on bots
  are worked out from the same clock and hazard maths the clients use. Each round can give a
  `BotGoal` saying what a bot should be doing right now (races get theirs from `RaceKit`'s
  route). `BotBrain` reads it a few times a second and decides (hazards to dodge, someone to
  kick, whether it's stuck); `BotMotor` steers the bot there every frame with a player's
  speeds and acceleration, easing off as it arrives, and does the quick reactions (jumping
  walls, ledges and gaps right at the edge, diving over wide ones). Grabs, kicks and dives go
  through the same `ActionService` checks players go through.
- **Matches** are run entirely by the server (`MatchService`). It publishes everything as
  attributes on `ReplicatedStorage.MatchState` and on each player (`MatchStatus`, `InMatch`,
  `Queued`, `SpectatingUserId`), and the UI just reacts to them. Clients can only ask to queue,
  switch who they spectate, or return to the lobby. While players wait for a round to start,
  their Bloblets are anchored by the server.
- **Saving** (`DataService`): each player's profile (Crowns, Gumdrops, items, what they wear,
  stats) is kept in a DataStore. Every call is retried with growing pauses. A session lock records which
  server has the profile open, so a player who hops servers waits for the old one to finish
  saving, and a server never overwrites data another server has taken over. Profiles autosave
  every minute, and when a player leaves or the server shuts down.
- **Rewards** (`ProgressService`): the match tells it what happened (a round started or ended,
  who got through, who won) and it hands out Gumdrops, Crowns and XP, updates stats and daily
  challenges, awards badges and sends each player their results. A level up pays out that
  level's reward track reward on the spot, and the profile remembers the highest level paid out,
  so nothing is ever paid twice. Exclusive items can only come from the track: the shop refuses
  to sell them. Challenge progress and
  settings are saved with the profile; clients only ever send their own settings, which the
  server clamps and checks.
- **Updates** (`SoftShutdown`): a closing server moves its players to a temporary holding server
  that only shows an updating screen, then on to a new server running the latest version.
- **Shop** (`ShopService`): buying, trading and wearing are requests the server checks against
  the saved profile (item exists, enough Crowns or Gumdrops, you own it, and a shop item is in
  today's or this week's cosmetic shop). The cosmetic shop is worked out from the date, so every
  server shows the same items without saving anything.
- **Items** (`ItemService`, `ActionService`, `MatchService`): how many of each item you have is in
  the saved profile, and only the server uses them up: a picked boost at GO, a slap when it
  lands, a respawn when you take it. Clients only ask (pick, slap, respawn); the server checks you
  have one and that it's allowed right then (picking only while your round loads, slapping only
  holding a slapper, respawns once per round). Boosts only change your movement while you're
  competing, and the server's speed check still applies. The slapper is built on your Bloblet by
  the server, so everyone sees it.
- **Robux** (`PurchaseService`): Crowns and items are only added when Roblox confirms a purchase. The
  purchase is recorded in the profile and saved before Roblox is told it's done; if anything goes
  wrong Roblox asks again later, and the record stops it being given twice. Emotes play whatever the
  server has on record as equipped. Crowns and Gumdrops are only ever handed out by the match
  server.
- **Rounds:** the type is picked at random, then a game of that type that hasn't been played this
  match. Round 1 prefers a race. From round 2, once 6 or fewer players remain (or at round 5),
  it's the Final. Each type lets a share of players through (Race 70%, Survival 60%, Team 50%),
  always at least one in and one out.
- **Races** never eliminate for falling: the server sees you drop below the course and moves you
  back to the furthest checkpoint you reached (`RaceKit`). Because clients move their own
  Bloblets, reaching a checkpoint or the finish only counts if you got there from where you were
  a moment earlier at a believable speed; a teleport sends you back to your checkpoint instead.
- **Conveyors and moving platforms** carry Bloblets because each client gives the anchored parts
  it animates the matching velocity. **Crates** are created by the server with their timings
  (when the shadow shows, when they land, how they slide) and every client plays and judges them
  from the shared clock.
- **Parties** (`PartyService`): invites, joining and leaving are requests the server checks
  (the player is here, the invite is still open, the party isn't full). `MatchService` queues a
  party together and `TeamService` puts each party on one team.
- **Friend bonus** (`FriendService`, `ProgressService`): the server checks who's friends with
  whom when players join, and at the start of a match works out each player's bonus from the
  friends in that match.
- **Leaderboards** (`LeaderboardService`): scores live in ordered DataStores, saved only when they
  change; the server reads the top 10 every couple of minutes and mixes in its own players'
  latest scores, and clients draw the boards.
- **Parkour** (`ParkourService`): like a race, checkpoints count in order and only from a
  believable move, finishes under 20 seconds don't count, and the profile remembers your first
  finish so the Gumdrops are only paid once. `ParkourBoardService` keeps one ordered DataStore per
  day (fastest first); after midnight each server looks up the last week's winners and pays any
  winner playing there, and the profile remembers which days it's been paid for.
- **Premium track** (`PremiumService`, `TrackRewards`): owning the pass is checked with Roblox
  when you join and remembered in your profile; a purchase is granted when Roblox tells the
  server (`PromptGamePassPurchaseFinished`), never because a client says so. Each track
  remembers the highest level it has paid (`TrackClaimed`, `PremiumClaimed`), so buying late pays
  every level you'd reached exactly once.
- **Tutorial** (`TutorialService`): every step is checked on the server (zones, and grabs and kicks
  the server accepted next to the dummies); the reward is paid once, recorded in the profile.
- **Grabbing** is held: while GRAB is held the server keeps looking for something in reach (every
  `Config.Grab.ReachInterval`) and grabs the first thing it finds, so nothing depends on pressing
  at exactly the right moment.
- **Eggs** (Egg Scramble) are server physics parts; picking one up goes through the server's grab
  (`ActionService.SetGrabHook`), and a carried egg is welded above its carrier.
- **The rope** (Tug of Wobble): taking hold goes through the grab hook too. Each JUMP while
  holding it sends `RequestPull`; the server ignores tugs faster than anyone can mash, works out
  each team's tugs a second and sets the rope's speed. Holders get an `OnRope` attribute (which way
  to face) and `Tow` (how fast the rope is moving); the client stands them still, facing that way,
  and moves them with the rope.
- **Spectating** points the spectator's streaming focus (`Player.ReplicationFocus`) at the player
  they watch, so that part of the world loads for them.

**Adding a mini-game**
1. Copy `src/server/MiniGames/_Template.luau` in the same folder and rename it, for example
   `HotPotato.luau` (no leading underscore).
2. Edit `Info`: `Id` (same as the file name), `DisplayName`, `Type` (`Race`, `Survival`, `Team` or
   `Final`), `Rules` (one line for the round card) and `Duration`.
3. Fill in `Setup` (build in `context.Arena` around `context.Origin`, then `context.SpawnAll`),
   `Start`, `Update` (runs about 10 times a second), `End` and `GetQualified`. The context gives
   you `Qualify`, `Eliminate`, `EliminateBelow`, `GetAlive`, the players' teams in team rounds,
   and more. See `src/server/Match/Types.luau`.
4. That's it: the registry finds it automatically. Use `StudioForceRounds` to test it alone.

**Adding things later**
- Ready-made pieces live in `src/server/Builders/Hazards.luau`: `Spinner` (speed it up mid-round
  with `SetSpinnerSpeed`), `BouncePad`, `Conveyor`, `MovingPlatform` / `Mover`, `Crate`,
  `Balloon`, `Gumdrop` (a roller that can run down a slope), `PaintPickup`, `Goo`, `Crown`,
  `Platform`, `Swinger` (anything that swings or tilts round a pivot, like King of the Cake's
  tiers), `Hammer` (a swinging hammer, on a frame or a single post) and `Spikes` (a trap that pops
  up on a timer, or stays up). Give any floor part a `Grip` attribute below 1 to make it slippery
  (Sugar Slopes' icing uses 0.2), or a `Flow` attribute (a Vector3, studs/s) to carry Bloblets
  along like water (Splash Slide: on water a belly slide lasts until you leave it and goes 15%
  faster than the water, and extra speed from a dive only fades slowly). Races use `src/server/Match/RaceKit.luau` (see
  `ConveyorCanyon.luau` for a full example; pass `Fallen` to decide "fell off" yourself).
- Rounds can listen to `ActionService.Acted` (every dive, grab, kick and slap the server accepts)
  and take over grabs with `ActionService.SetGrabHook` (see `EggScramble.luau` and
  `TugOfWobble.luau`; the hook is told whether GRAB was just pressed or is being held); clear the
  hook in `End`.
- Any round can show a button prompt low in the middle of the screen: set a player's `RoundPrompt`
  attribute to one of the prompts in `src/client/Controllers/RoundPrompt.luau` (add your own
  there), and clear it in `End`.
- Any round can show a meter at the top of the screen: set the `ScoreLabel` and `ScoreGoal`
  attributes on `Match.GetFolder()` and each player's `RoundScore` attribute, and clear them all in
  `End` (see `KingOfTheCake.luau`).
- Team rounds get their teams in `context.Teams`, can show live scores with
  `context.SetTeamScores` (the team score bar) and change the counter with
  `context.SetCounterText`. See `PaintGrab.luau` and `GumballGoal.luau`. Any round can pop up a
  message for everyone with `context.Announce(text, teamId?)`.
- Under the hood they're tags plus attributes that every client animates automatically: a model
  `Spinner` (`Speed`/`Phase`, a `Hub` and an `Arm`; optional `GraceUntil`), a part `BouncePad`
  (`Power`), `Riser` (`StartTime`/`Rate`/`MaxRise`; negative values sink), `Wobbler`
  (`Amplitude`/`Speed`/`Phase`), models `FallingTile` (a `Pad` part and a `FallAt` time; optional
  `WarningTime` and `Popcorn`), `Conveyor` (a `Belt` part, `Slat` parts and `Speed`), `Mover`
  (`Travel`/`Speed`/`Phase`), `Crate` (`LandAt`, `DropHeight`, `SlideVelocity`, `SlideTime`),
  `Roller` (`StartAt`, `Origin`, `Velocity`, `Duration`, `Diameter`, `Hop`, `HopRate`, a `Ball`,
  and `LaneFrom`/`LaneTo` for the arrows), `PaintPickup` (`Kind`; bursts when it gets a
  `SplashColor`), `Slider` (a model the server slides along its `Axis`: `Offset` studs at server
  time `At`, then `Velocity` studs/s, between `Min` and `Max`; Tug of Wobble's rope), `Swinger` (a `Pivot` primary part, `Amplitude` (Vector3, radians)/`Speed`/`Phase`;
  `Hits` and a `Head` part make it knock people over), `Spikes` (a `Plate` primary part, `Spike`
  parts, `Period`/`UpTime`/`Phase`/`Height`; Period 0 = always up) and `Jelly` (a `Pad` primary part,
  `Level`/`Rate`/`At`/`SinkDepth`/`Gone`).
- Sounds: `src/client/Controllers/Sfx.luau` lists every sound as layers of built-in Roblox
  sounds (pitched and timed into little tunes). Swap any of them for your own uploaded audio
  there, and play new ones with `Sfx.Play(name)` or `Sfx.PlayAt(name, position)`.

## 6. Publishing Wobble Rush

Roblox moves its menus around from time to time; if a button below has moved, the Creator Hub
documentation (create.roblox.com/docs) has the current location.

### Before you publish

1. In `src/shared/Config.luau`, check `StudioForceRounds = table.freeze({})`,
   `Config.Studio.LoadTestBots = 0`, `Config.Studio.ShowBotThoughts = false`,
   `Config.Studio.ProfileBots = false`, `Config.Bots.FillTo = 12`,
   `Config.Studio.EveryoneIsFriends = false`,
   `Config.Studio.ParkourDayMinutes = 0`, `Config.Studio.ShopDaysAhead = 0`,
   `Config.Studio.TestPremium = false`, `Config.Studio.ResetPremium = false` and
   `Config.Studio.DoubleXP = "Auto"`. Published games
   ignore all of them anyway, but it keeps Studio honest.
2. Build the place file fresh so every setting from `default.project.json` is in it:
   `rojo build -o WobbleRush.rbxl`, open it in Studio, and connect Rojo once to make sure the
   code is current.
3. Run a match in Studio with **Clients and Servers** (2–4 players) and check the Output has no
   red errors.
4. Decide on bots (`Config.Bots`). With `Enabled = true` (the default), one player pressing PLAY
   starts a 15-second countdown and bots fill the match up to 12, so nobody waits for a full
   server. With `Enabled = false`, a match needs `Config.Match.MinPlayers` (4) players.

### Publish

1. In Studio: **File → Publish to Roblox** (the first time it asks for a name and description;
   after that it updates the same game).
2. **Home → Game Settings**:
   - **Basic Info**: name, description, genre, and the devices it plays on. Wobble Rush supports
     computer, phone, tablet and console (controller), so tick them all.
   - **Security**: turn on **Enable Studio Access to API Services** (lets Studio test saving;
     live servers always save).
3. **Server size**: Wobble Rush is built for up to 30 players. In the Creator Dashboard
   (create.roblox.com → Creations → your experience), open **Places**, choose the place and set
   its maximum players / server size to **30**.
4. **Maturity questionnaire**: in the Creator Dashboard, fill in your experience's maturity and
   compliance questionnaire (Audience section). Wobble Rush is cartoon bumping with no blood,
   weapons or chat beyond Roblox's own.
5. **Icon and thumbnails**: take a few screenshots in Studio (lobby, a race, the winner's
   celebration) and upload them as the icon and thumbnails on the experience's page in the
   Creator Dashboard.
6. When you're ready, make it **Public** (Creator Dashboard → your experience → its privacy /
   visibility setting).

### Leaderboards and invites

- The leaderboards use ordered DataStores, so they need the same access as saving: published, and
  (to see them in Studio) **Enable Studio Access to API Services**. They start empty and fill up
  as people play; to wipe them all and start again, raise `Config.Leaderboards.StoreVersion`.
- The **INVITE** button uses Roblox's own invite screen, which only appears in the published game
  (and only for players allowed to send invites).

### Crown packs (Robux)

1. Creator Dashboard → your experience → **Monetization → Developer Products → Create a Developer
   Product**, five times: **5 Crowns**, **15 Crowns**, **40 Crowns**, **100 Crowns** and **500
   Crowns**, each with an icon and a Robux price. Suggested prices: 49, 129, 299, 649 and 2,999
   Robux (bigger packs are better value).
2. Copy each product's id into `Config.CrownPacks` in `src/shared/Config.luau`, in the same
   order (`ProductId = 0` means not set up: that pack says COMING SOON).
3. Publish, then test in Studio: buying shows a test prompt that costs nothing, and the Crowns
   arrive. Turn on **Enable Studio Access to API Services** to check they're saved.

### Item packs (Robux)

The ITEMS shop sells items for Robux only (Crowns can't buy them). Each card is one Developer
Product, set up like the Crown packs:

1. Creator Dashboard → your experience → **Monetization → Developer Products**, eight of them.
   Suggested names and prices (the amount each pack gives is in `Config.Items.Packs`):

   | Product | Gives | Suggested price |
   | --- | --- | --- |
   | 10 Slaps | 10 slaps | 25 Robux |
   | 3 Respawns | 3 respawns | 49 Robux |
   | Speed Boost x3 | 3 rounds | 39 Robux |
   | Jump Boost x3 | 3 rounds | 39 Robux |
   | Double Jump x3 | 3 rounds | 39 Robux |
   | Slide Boost x3 | 3 rounds | 25 Robux |
   | Shield x3 | 3 rounds | 39 Robux |
   | Double Rewards x2 | 2 rounds | 49 Robux |

   And one more for the revive (knocked out, no RESPAWNS: buy one to come back for the match's
   next round; one a match): **Revive**, 1 respawn (used straight away), suggested 25 Robux.
   Paste its id into `Config.Items.ReviveProductId` (0 = not sold; players with a RESPAWN can
   still revive).

2. Paste each id into `Config.Items.Packs` in `src/shared/Config.luau` (the `Item` names must stay
   as they are; you can change `Amount`). `ProductId = 0` shows COMING SOON. Players pick which
   items to use at the start of each round; a boost, shield or double rewards lasts that round.
3. How strong they are is in `Config.Items` (speed, jump and slide multipliers, respawns per
   round, respawns in the final on or off, revives a match) and `Config.Slap`. Boosts that are too strong can put
   off players who don't buy them, so keep them small.

### Premium reward track (Game Pass)

The PREMIUM track is one Game Pass: buy it once and it's yours for good.

1. Creator Dashboard → your experience → **Monetization → Passes → Create a Pass**. Name it e.g.
   "Premium Reward Track", give it an image and a description ("A second, bigger reward at every
   level, 9 premium-only items, and everything you've already reached straight away").
2. Open the pass, turn on **Item for Sale** and set a price (around 199 to 499 Robux is common for
   a track like this).
3. Copy the pass id (the number in its URL) into `Config.Premium.GamePassId` in
   `src/shared/Config.luau`. Until it's set, the UNLOCK button says NOT SET UP YET.
4. What each level gives is in `src/shared/Progression.luau` (`PREMIUM_CROWNS`, `PREMIUM_PACKS`) and
   the premium-only items are the `premium(...)` ones in `src/shared/Cosmetics.luau`.

Owning the pass is checked with Roblox when a player joins and remembered in their saved data, so
a player who bought it on the website gets everything when they next join.

### Music (optional)

Every round already has its own song made from Roblox's built-in sounds. To use real music
instead, upload or pick tracks you're allowed to use (the Creator Store's **Audio** section has
music licensed for Roblox games), and put their asset ids in `Config.Music.Tracks`, e.g.
`table.freeze({ Lobby = 1234567890, Race = 2345678901, SplashSlide = 3456789012 })`. A round uses
its own id first, then its type's (`Race`, `Survival`, `Team`, `Final`). Pick tracks that loop
cleanly; the 10-second HURRY speeds them up a little.

### Double XP weekends

They run by themselves every Friday 18:00 to Monday 00:00 UTC (`Config.Events.DoubleXP`). For a
one-off event (a holiday, a big update) add a window to `Extra`, e.g.
`{ From = 1767225600, To = 1767398400 }` (unix times; any "epoch converter" website gives them).

### Badges (optional)

1. Creator Dashboard → your experience → **Engagement → Badges → Create a Badge**, four times:
   *First Qualify* (get through any round), *Finalist* (play in a final), *Champion* (win a match)
   and *Ten Wins* (win 10 matches). Each needs a name, a description and a square image.
2. Copy each badge's id (the number in its page's address) into `Config.Badges` in
   `src/shared/Config.luau`: `FirstQualify`, `ReachFinal`, `FirstWin`, `TenWins`.
3. Publish again. Badges are only awarded in the live game, not in Studio.

### Updating a live game

1. Make your changes, test in Studio, then **File → Publish to Roblox**.
2. New servers start on the new version straight away. To move everyone already playing, use
   **Restart Servers for Updates** (in the Creator Dashboard, on your experience's ⋯ menu; Studio
   also offers it after publishing). Thanks to `SoftShutdown`, players see an "Updating" screen and
   land in a new server a few seconds later instead of being disconnected; their data is saved on
   the way.

### Testing on other devices

- In Studio, the **Test** tab's device emulator shows phone, tablet and console layouts (touch
  buttons, see-through panels, controller hints).
- On a real phone: open your game in the Roblox app (it can stay private while only you play it).
- With a controller on PC: plug it in and play in Studio or the Roblox app; every menu works with
  it (the lobby MENU with LT, the customise screen with D-pad right, settings with D-pad left,
  rewards with D-pad down, the party screen with LB; in a round LT grabs and RT slaps when you're
  holding a slapper).
