# Wobble Rush

An original Roblox party-royale for up to 30 players. Round, squishy **Bloblets** wobble through
randomly shuffled mini-game rounds until one winner is left.

This repository is a [Rojo](https://rojo.space) project: all game code is Luau in `src/`, and
Rojo syncs it into Roblox Studio. The lobby, characters and UI are all generated by code, so
there are no models or images to upload.

## 1. Connecting Rojo to Roblox Studio

You need three things: this folder on your computer, the Rojo command-line tool, and the Rojo
plugin inside Studio.

### Get the code

```bash
git clone https://github.com/eminhqn/rblxfllgys.git
cd rblxfllgys
```

### Install Rojo (choose one)

**Option A: VS Code (easiest)**
1. Install [Visual Studio Code](https://code.visualstudio.com/) and open this folder in it.
2. Accept the "recommended extensions" prompt. That installs Rojo, Luau Language Server,
   StyLua and Selene (listed in `.vscode/extensions.json`).
3. Open the command palette (`Ctrl+Shift+P`) and run **Rojo: Open Menu**. It will offer to
   install Rojo and the Studio plugin for you.

**Option B: Rokit (command line)**
1. Install [Rokit](https://github.com/rojo-rbx/rokit).
2. In this folder run `rokit install`. That installs the exact tool versions in `rokit.toml`
   (Rojo 7.7.1, Selene, StyLua, luau-lsp).
3. Run `rojo plugin install` to add the Rojo plugin to Studio.

### First time: build the place file

Some settings (streaming, lighting, "don't load the default avatar") can't be changed by live
sync, so build the place once and open it:

```bash
rojo build -o WobbleRush.rbxl
```

Open `WobbleRush.rbxl` in Roblox Studio, then **File → Save to Roblox** if you want it in your
account. You only need to rebuild if `default.project.json` changes.

### Every session: live sync

1. In the terminal (or the VS Code Rojo menu): `rojo serve`
2. In Studio: **Plugins** tab → **Rojo** → **Connect** (default `localhost:34872`).
3. Edit files in `src/`. Changes appear in Studio straight away.

> Always edit the code in `src/`, not inside Studio. Rojo overwrites script changes made in
> Studio.

## 2. Testing in Studio

Press **Play** (F5) for a solo test. For multiplayer checks (grabbing, eliminations, spectating),
use **Test** tab → **Clients and Servers** → choose **2–3 players** → **Start**.

Keep the **Output** window open (View → Output). There should be no red errors.

> **One-time setting for Milestone 2:** select **Workspace** in the Explorer and set
> **StreamingIntegrityMode** to **MinimumRadiusPause** in Properties (or rebuild the place with
> `rojo build`). It makes sure the arena has loaded around you before you can fall.

### Milestone 2 checklist: matches

**Solo (F5)**
- [ ] Under the **WOBBLE RUSH** badge there's a panel with a big **PLAY** button and the line
      "Press PLAY to join the next match". The big screen in the lobby says the same.
- [ ] Press **PLAY**: it turns into **CANCEL**, and the panel and big screen count down
      "Match starts in 0:08". In Studio the countdown is 8 s and one player is enough. Published
      games need 4 players and count down 30 s, or 5 s once 30 players are queued.
- [ ] At zero, a pink wipe covers the screen and you appear on **Rising Tide's** island, frozen.
      A round card shows the type (SURVIVAL), the name and the rules, then **3, 2, 1, GO!**.
- [ ] The round bar at the top shows SURVIVAL, ROUND 1, RISING TIDE, a timer and a live counter.
- [ ] The water rises steadily. Climb the spiral planks round the candy pillar: every fourth
      plank wobbles and every sixth gap is wider.
- [ ] **Fall into the water:** you splash, get knocked over and float on the surface. A pulsing
      **GET OUT OF THE WATER! 3.5** countdown appears. Swim (slower than running) to a plank and
      jump out before it hits zero and you're safe; you have to stay out for a moment for the
      timer to reset, so hopping in place doesn't work. Run out of time: **ELIMINATED!**, then a
      wipe and you're back in the lobby.
- [ ] **Reach the golden top** (the floating QUALIFY! label): **QUALIFIED!** straight away. Alone
      in Studio that ends the round; with more players it ends once every qualifying spot is
      taken. If the timer runs out first, everyone still dry qualifies (but not anyone floating).
- [ ] **Cloud Crown**: a big cloud under a spinning golden crown. Puffs about to go **flash
      pink**, faster and faster for 3 seconds, shake at the very end, then drop: first the edge,
      and twice along a line that splits the cloud.
- [ ] When the final ends, everyone sees the **WINNER!** banner with confetti, and the winner
      stands on the gold podium in front of the lobby screen. (Alone in Studio you win the final
      even if you fall, because nobody else is left.) After about 9 s everything resets and
      PLAY works again.

**Multiplayer (2–3 test players, everyone presses PLAY)**
- [ ] With 3 players, 2 qualify from Rising Tide: the round ends when 2 have reached the top or
      once the first player drowns (try kicking someone off a plank).
- [ ] The eliminated player sees **ELIMINATED!**, then a spectate bar: **SPECTATING** + a name,
      **<** / **>** to switch (Q / E, or LB / RB), and **BACK TO LOBBY** (or B). Their camera
      follows players in the arena while their own Bloblet waits in the lobby.
- [ ] **BACK TO LOBBY** brings the camera home and shows the PLAY panel again. You can queue for
      the next match while the current one is still going.
- [ ] Players who didn't press PLAY stay in the lobby and see "Match in progress" on the panel
      and the big screen.
- [ ] Closing a test client mid-round doesn't break the match.
- [ ] Teams: no team game exists yet (Paint Grab comes in Milestone 4), so you won't see teams
      in a match yet. The round manager already splits players into random teams when a team
      round starts.

**Testing one mini-game:** in `src/shared/Config.luau` set
`StudioForceRounds = table.freeze({ "CloudCrown" })` (or `"RisingTide"`). Set it back to
`table.freeze({})` when you're done.

### Milestone 1 checklist: character and lobby

**Spawning and lobby**
- [ ] You spawn on one of the four raised decks as a Bloblet (round body, cartoon eyes, stubby
      arms, floppy feet). Your normal Roblox avatar does not appear.
- [ ] The top of the screen shows the **WOBBLE RUSH** badge.
- [ ] **Nobody has a team in the lobby**: no team outline, no team chip and no team headers in
      the player list. Teams are picked at random only when a team round starts; then the chip
      and thin team-colour outlines appear.
- [ ] Each deck has tinted glass walls, a sign and four spawn pads. You can walk down the
      stairs to the plaza and back up.
- [ ] The big screen at the far end shows `players / 30`, updating as test players join and
      leave, plus a matchmaking line.

**Movement feel**
- [ ] WASD ramps up smoothly, stops quickly and turns sharply. The body leans into the movement.
- [ ] Tap Space for a short hop, hold it for a full jump.
- [ ] **Coyote time:** run off the edge of a foam step and press jump just after leaving it. You
      still jump.
- [ ] **Jump buffering:** press jump just before you land. You jump again the moment you touch
      down.
- [ ] Squash on landing (with a jelly wobble), stretch in the air, idle breathing, blinking, and
      eyes that look where you're moving.

**Moves**
- [ ] **Dive** (Ctrl or C): belly-flop forward. Steer it a little in mid-air with the stick or
      keys. You land in a short slide you can steer, and **pressing jump during the slide cancels
      it into a jump that keeps the dive's speed**. **Holding the opposite direction brakes**: it
      slows the dive in mid-air and stops the slide almost on the spot (try landing on the far
      platform of the jump course). Roughly a 1 s cooldown.
- [ ] **Air control:** you can change direction and stop in mid-air easily.
- [ ] Practice course (right side): climb the three foam steps and **jump, then dive** across
      the gap. A jump alone falls short.
- [ ] **Bounce pad** (left side): launches you high. Steer onto the floating platform.
- [ ] **Spinner** (centre): getting hit near the end of the bar knocks you over. You tumble, the
      camera shakes, your eyes spin, and you get up after 1–2 s. Near the hub it only pushes you.
      You can jump over the bar.
- [ ] **Grab** (hold Shift or E, 2+ players): face another Bloblet up close and hold. They slow
      down and get tugged towards you, and their eyes go wide. Let go to release. It auto-releases
      after 3 s or if you get too far apart.
- [ ] **Kick** (F or left click, gamepad B, KICK button on mobile; 2+ players): your foot swings
      out. A Bloblet right in front of you gets knocked over and pushed away (the server decides
      who you hit). About a 1 s cooldown.

**Devices**
- [ ] **Mobile:** Test tab → Device → pick a phone. A thumbstick appears where you touch on the
      left, and Jump / Dive / Grab / Kick buttons on the right. Dive and Kick darken while cooling
      down. The keyboard hint is hidden.
- [ ] **Gamepad:** plug one in. The controls card switches to gamepad buttons (A jump, X dive,
      R2 grab, B kick, left stick move).
- [ ] UI stays readable when you resize the Studio window.

**Safety nets**
- [ ] Esc → **Reset Character** gives you a fresh Bloblet on your deck.
- [ ] Jump over the plaza bumpers and walk far away. You are respawned once you're about 420
      studs from the centre.

If something feels off, most of the feel is tunable in `src/shared/Config.luau` (speeds,
acceleration, jump height, coyote and buffer windows, dive, grab and ragdoll values).

## 4. How it's built

```
src/
  shared/   (ReplicatedStorage.Shared)            used by server and client
    Config        all tuning numbers; the server validates with the same values
    BlobletRig    builds the Bloblet model in code
    Remotes       creates/gets the RemoteEvents
    Teams, Theme, Ui, Tags, HazardMath, MathUtil, Signal
    Match         match phases and attribute names shared by server and UI
  server/   (ServerScriptService.Server)
    Main.server   starts the services in order
    Services/     CharacterService, TeamService, ActionService, MovementValidator,
                  LobbyService, PlayerState, EnvironmentService
    Match/        MatchService (queue -> rounds -> winner), RoundContext, MiniGameRegistry,
                  SpectateService, Types (the mini-game interface), ArenaUtil
    MiniGames/    one module per mini-game: RisingTide, CloudCrown, _Template (copy me)
    Builders/     LobbyBuilder, Backdrop, Geometry (rounded "inflatable" parts)
  client/   (StarterPlayerScripts.Client)
    Main.client   starts the controllers
    Controllers/  InputController, TouchControls, MovementController, BlobletAnimator,
                  HazardController, TeamOutlines, CameraFX, Sfx, Hud, ResponsiveScale,
                  MatchClient, MenuController, RoundHud, SpectateController,
                  TransitionController
```

**Who decides what**
- **Movement** runs on your own device (Roblox gives each player ownership of their character's
  physics), so it responds instantly. The server checks positions twice a second and snaps back
  impossible speed or teleports (`MovementValidator`).
- **Dive and grab** play instantly on your screen, and a request goes to the server. The server
  checks cooldowns and state, picks the grab target itself, and publishes the result as
  character attributes (`Action`, `Grabbing`, `GrabbedBy`, `Ragdolled`). Other clients animate
  from those. Rejected requests cancel the local prediction.
- **Every remote** is rate-limited and type-checked on the server (`ActionService`,
  `CharacterService`). Clients only send intent, never results.
- **Moving hazards** are animated on each client from the shared server clock, so the server
  sends no per-frame data. Everyone sees the same pose, and hits are judged against what you
  actually see.
- **Animation** (squash/stretch, eyes, feet) is client-only via `Motor6D.Transform` and
  `SpecialMesh.Scale`, with distance-based detail reduction for 30 players.
- **Matches** are run entirely by the server (`MatchService`). It publishes everything as
  attributes on `ReplicatedStorage.MatchState` and on each player (`MatchStatus`, `InMatch`,
  `Queued`, `SpectatingUserId`), and the UI just reacts to them. Clients can only ask to queue,
  switch who they spectate, or return to the lobby. While players wait for a round to start,
  their Bloblets are anchored by the server.
- **Rounds:** the type is picked at random, then a game of that type that hasn't been played this
  match. Round 1 prefers a race. From round 2, once 6 or fewer players remain (or at round 5),
  it's the Final. Each type lets a share of players through (Race 70%, Survival 60%, Team 50%),
  always at least one in and one out.
- **Spectating** points the spectator's streaming focus (`Player.ReplicationFocus`) at the player
  they watch, so that part of the world loads for them.

**Adding a mini-game**
1. Copy `src/server/MiniGames/_Template.luau` in the same folder and rename it, for example
   `HotPotato.luau` (no leading underscore).
2. Edit `Info`: `Id` (same as the file name), `DisplayName`, `Type` (`Race`, `Survival`, `Team` or
   `Final`), `Rules` (one line for the round card) and `Duration`.
3. Fill in `Setup` (build in `context.Arena` around `context.Origin`, then `context.SpawnAll`),
   `Start`, `Update` (runs about 10 times a second), `End` and `GetQualified`. The context gives
   you `Qualify`, `Eliminate`, `EliminateBelow`, `GetAlive`, the players' teams in team rounds,
   and more. See `src/server/Match/Types.luau`.
4. That's it: the registry finds it automatically. Use `StudioForceRounds` to test it alone.

**Adding things later**
- New hazards: tag a model `Spinner` (with `Speed`/`Phase` attributes, a `Hub` and an `Arm`), a
  part `BouncePad` (`Power`), `Riser` (`StartTime`/`Rate`/`MaxRise`), `Wobbler`
  (`Amplitude`/`Speed`/`Phase`), or a model `FallingTile` (a `Pad` part and a `FallAt` time), and
  every client animates it automatically.
- Sounds: `src/client/Controllers/Sfx.luau` has a hook per sound. Grab and UI clicks are silent
  until you add an uploaded sound ID. The others reuse built-in Roblox sounds.

## 5. Development checks

These run without Studio:

```bash
rojo build -o WobbleRush.rbxl                     # project builds
rojo sourcemap default.project.json -o sourcemap.json
luau-lsp analyze --platform=roblox --sourcemap=sourcemap.json \
  --definitions=globalTypes.d.luau src            # strict type check (see below for definitions)
selene src                                        # lint
stylua --check src                                # formatting
```

`globalTypes.d.luau` is the Roblox API type definition file from the
[luau-lsp repository](https://github.com/JohnnyMorganz/luau-lsp/tree/main/scripts)
(`globalTypes.None.d.luau`). The VS Code extension downloads it automatically.
